# 更新產業鏈上游訊號（雲端排程的工作說明）

這份是給雲端排程裡的 Claude 看的步驟。每月 1 日與 16 日執行一次，用你的 Claude 帳號上網查資料，不需要 API key。

目標：把 `site/data/chain_inputs.json` 裡「待更新」或太舊的上游訊號補上最新數字，讓產業鏈燈號不只看月營收。

1. 讀 `site/data/chain_inputs.json`。挑出要更新的項目：
   - `trend` 是 `null`（待更新）的；
   - `as_of` 距今超過 45 天的。
   一次最多處理 12 項，優先處理 `null` 的；其餘留到下次。
2. 每一項用網路搜尋找「最新一期」的公開數字，優先用該項 `url` 指向的來源（TrendForce、SEAJ、公司法說、政府統計），找不到再用主要財經媒體的報導。
3. 判斷方向並填寫：
   - `trend`：`up`（對這條鏈的基本面轉強：報價上漲、出貨或訂單成長、指引上修）、`down`（轉弱）、`flat`（變化不大，約在 ±3% 內或說法持平）。
   - `value`：一句話寫出數字與期間，40 字內，例如「11 月 DDR5 合約價月增 8%，連三個月上漲」。
   - `as_of`：這個數字所屬的日期，`YYYY-MM-DD`；只知道月份就寫 `YYYY-MM`。不是今天的日期。
   - `url`：你實際讀到這個數字的網頁連結。
4. 規則：
   - 查不到明確數字、來源互相矛盾、或只找到超過 3 個月前的資料：**不要猜**，保持原樣（`trend` 留 `null`），在最後回報裡列出來。
   - 不要自己推算或補數字；不要更動 `name`、鏈代號、`_說明`，也不要新增或刪除項目。
   - 成本類訊號照字面判斷價格方向即可（程式會處理對下游是利多還是利空）。
5. 執行 `python -m briefing.inputs_file check site/data`，有 ✗ 就修到全部通過。
6. 只提交 `site/data/chain_inputs.json`，訊息用 `上游訊號 YYYY-MM-DD`，推到 `main`。沒有任何項目更新就不要提交。
7. 最後用繁體中文回報：更新了哪幾項（各一行：名稱、方向、數字）、哪幾項查不到。
